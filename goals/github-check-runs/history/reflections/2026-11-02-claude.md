# Reflection: github-check-runs (2026-11-02, claude)

## Summary

Shipped a `nitpick` check run per PR head in PR #1: `in_progress`, then `success` or `failure` by `checks.failOn`, `neutral` on errors, `skipped` on skip rules, carry-forward on un-reviewed pushes, Re-run via `check_run.rerequested`. Two reviewer rounds; one real gate bypass found and fixed.

## Tooling experience

- **Worked:** the GitHub fake at the service seam made every check path testable on PGlite; the explore packet gave the implementation a settled decision log, so no design reopened mid-build.
- **Didn't:** `exactOptionalPropertyTypes` against octokit params forced explicit param building; anti-slop rejected the conditional-spread shortcut.
- **Frustrating:** vitest path filters silently match nothing in this workspace.
- **Wished existed:** a fake-GitHub helper for check runs shared across test files.

## Implementation improvement opportunities

- Store the run id atomically with creation (needs an idempotent create keyed by `external_id`).
- Log GitHub's error message for swallowed check writes, after checking it carries no PR content.

## Goal and prompt critique

- GOAL.md should flag that merge deploys and needs the Checks permission, so the operator step is planned, not discovered.

## TODOs worth codifying

- CLAUDE.md: vitest `--project` usage.

## Lessons (confidence-tiered)

- **HIGH:** A required check's conclusion on a SHA must derive from that SHA's own judgment first; anything "carried" is a bypass surface.
- **MEDIUM:** Every webhook branch that queues paid work needs a test that other actions of the same event queue nothing.
- **LOW:** Time-box third-party writes inside finalizers.
